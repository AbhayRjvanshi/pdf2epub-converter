# Hybrid PDF → EPUB3 Converter — Project Analysis

## What It Is

A **two-tier, hybrid PDF-to-EPUB3 pipeline** written in pure Python. Its core design goal is to convert PDFs into valid, accessible, reflowable EPUB3 books — as cheaply and correctly as possible — by sending **only genuinely difficult pages to an AI model**, while handling everything else with a deterministic (free, offline) engine.

Verified performance: **11.7 s, 95 MB RAM** for a 500-page book, producing **EPUBCheck-clean output (0 errors, 0 warnings)**.

## How Each Phase Works

### Phase 1–2: Document Open & Font Profiling
- Opens the PDF with **PyMuPDF** (`pymupdf`/`fitz`)
- Samples up to 160 pages to compute the **document-wide font profile**: dominant body font, body size, and line height (weighted by character count so short headings don't skew the baseline)
- Reads title/author from PDF metadata if not provided on the CLI

### Phase 3: Triage & Routing (`confidence_router.py`)

Every page is evaluated **once** (one `get_text("dict")` call), scored 0–100, and routed:

| Route | Score | Means |
|---|---|---|
| **Tier 1** (free) | ≥ 85 | Clean, simple page |
| **Tier 2 digest** (paid) | < 85 | Complex layout — sends bbox + typography JSONL |
| **Tier 2 vision** (paid) | 0 (forced) | No text layer / corrupted CMap — sends 150 DPI PNG |

**Scoring penalties** (deducted from 100):

| Signal | Threshold | Max penalty |
|---|---|---|
| Weighted font σ | > 3.5 pt | −35 |
| Reading-order violations | > 0 | −45 |
| Vector path density | > 20 | −30 |

**Sanity gate** (checked first — fails → vision path):
- No text layer at all
- > 15% private-use / control characters (CMap corruption)
- Stopword hit-rate < 8% on substantial pages (gibberish detection)

Reading-order violations are measured only over the **body band** (middle 80% of page height) to avoid false positives from running headers/footers.

Payloads (rasters and digests) are **built lazily** one batch at a time and released immediately — critical for keeping RAM bounded on large documents.

### Phase 4A: Tier 1 — Deterministic Extraction (`tier1_classifier.py`)

For clean pages:
1. **Classify spans** by size ratio vs. body baseline → maps to `h1`–`h4`, `p`, `small`
2. **Build paragraphs** — merges wrapped lines using vertical gap + right-margin proximity + hyphen detection
3. **Emit XHTML** — `<p>`, `<h1>`–`<h4>`, `<strong>`, `<em>`, `<pre>`, `<small>`
4. **Extract images** — raster images spooled to temp dir, deduplicated by content-hash

Key bug fixes baked in:
- Fragment merging for PDFs with very wide word spacing (each word emitted as its own line)
- Space recovery from glyph gaps via `rawdict`
- 75th-percentile margin + next-word-fit test to avoid one overhanging line poisoning wrap detection
- Contiguous code-listing merge → `<pre>` with indentation from geometry

### Phase 4B: Tier 2 — AI Extraction (`tier2_llm_handler.py`)

For complex pages, two paths:

**Digest path** (text pages with complex layout):
- Sends a JSONL payload: `{line_id, block_id, bbox, size, bold, italic, text}` per line
- Batched: up to 4 pages per API call (configurable)
- Instructs the model to reconstruct reading order from coordinates, handle multi-column, emit `<table>`, `<aside>`, etc.

**Vision path** (scanned / image-only pages):
- Sends a 150 DPI PNG as base64
- Model performs OCR + semantic markup

Both paths:
- **Composite cache**: SHA-256 of `payload + system_prompt + model_id + temperature + schema_version` — editing a prompt auto-invalidates cache
- **XHTML repair gate**: fence stripping → entity fix → void normalisation → tag whitelist → lxml structural repair → plain-text fallback (never propagates broken markup)
- **Batch integrity**: if model returns wrong number of pages, re-prompts page-by-page then falls back to deterministic rendering
- Supports **OpenAI** (`gpt-4o` default) and **Anthropic** (`claude-sonnet-4-5`) — or offline mock mode

### Phase 5: Unified Stream Merge
- All per-page `StreamElement` lists are concatenated in page order into one flat list
- `StreamElement` is a dataclass carrying: `element_type`, `tag`, `content`, `page_num`, `block_id`, `level`, `css_class`, `image_path`

### Phase 6: Packaging (`packaging_and_validation.py`)

The assembled stream is processed before packaging:

1. **Furniture stripping** — removes running headers/footers: must appear on > 60% of pages, ≤ 90 chars, in the top/bottom 12% of page, at least 4 pages seen and 3 occurrences. Orphan page numbers (`\d{1,4}` / roman numerals) are deleted unconditionally.
2. **Cross-page paragraph welding** — detects paragraphs cut at page seams (no terminal punctuation, continues on next page) and joins them — hyphen-aware
3. **Chapter segmentation** — cuts at heading elements, not page numbers
4. **EPUB3 assembly** via `ebooklib`:
   - One XHTML file per chapter
   - NCX + navigation document (TOC)
   - Stylesheet with relative hrefs (to avoid EPUBCheck `RSC-007`)
   - Body-level markup only passed to `EpubHtml.set_content` (to avoid ebooklib's silent empty-chapter bug)
5. **Accessibility metadata** — computed from the actual output tree:
   - `structuralNavigation` — only if a heading tree exists
   - `alternativeText` — only if all images have non-empty alt text
   - `tableOfContents` — only if tables were emitted
   - `dcterms:conformsTo EPUB Accessibility 1.1 - WCAG 2.0 Level AA`

### Phase 7: Validation & Self-Repair

1. **Internal structural checker** — inspects chapter files for required XHTML elements, malformed markup
2. **EPUBCheck** (Java, optional) — runs `epubcheck.jar`, parses ERROR/FATAL lines
3. **Ace by DAISY** (Node, optional) — runs accessibility check, reads `earl:impact` / `earl:outcome`

If validation fails, up to `--max-repair-attempts` (default 2) self-repair passes:
- Re-sanitises every element through the XHTML repair gate
- Identifies failing chapters, re-prompts Tier 2 for those specific pages with the validator error injected
- Rebuilds and re-validates

## CLI Usage

```bash
# Fully offline (free, deterministic only)
python main.py book.pdf -o book.epub --provider none

# With OpenAI for complex pages
export OPENAI_API_KEY=...
python main.py book.pdf -o book.epub --title "My Book" --author "A. Name"

# With Anthropic
export ANTHROPIC_API_KEY=...
python main.py book.pdf -o book.epub --provider anthropic --model claude-sonnet-4-5

python main.py book.pdf --report-only
```

Exit codes: `0` = success, `1` = conversion/validation failure, `2` = bad input.

## Key Design Decisions

1. **Asymmetric cost model for routing errors**: A false negative (complex page going to Tier 1) causes silent data corruption; a false positive only wastes ~$0.002. The threshold is calibrated to eliminate false negatives.

2. **The unified stream is the central design**: Page boundaries are not file boundaries. By producing one flat element list, cross-page paragraph welding and book-level heading detection become straightforward.

3. **Lazy payload materialisation**: The router stores scores, not data. PNG rasters and JSONL digests are built only for the batch currently being processed, then released — keeping RAM flat regardless of document size.

4. **Honest accessibility metadata**: Conformance claims are derived from the actual output tree after conversion, never asserted by default.

5. **No "fail fast" on API or markup errors**: Every failure has a graceful fallback: bad batch → per-page retry → deterministic fallback → plain-text fallback. The pipeline always produces *something*.

Problem 1: pytest.ini — testpaths = tests with no tests/ directory

Problem 2: Offline Tier 2 — Line-per-<p>, no paragraph merging
The risk: Visibly degraded output in offline mode. Someone using --provider none on a complex page gets word-salad paragraphs.

Options
Option A — Port Tier 1's paragraph builder into the fallback (recommended) _digest_fallback() already has the digest — which includes bbox, block_id, and size per line. Those are exactly the inputs Tier 1's paragraph merging uses. You could run a simplified version of the same logic: group lines by block_id, check vertical gap against modal line height from the digest, check right-edge proximity against the block's right margin, and merge. This is entirely local arithmetic — no new dependencies.

The key insight: the digest was built for the LLM to understand layout, but it contains enough geometry to do rudimentary paragraph assembly offline too. You're not adding a new data source, just using the existing one more fully.

Option B — Use block_id alone as a grouping proxy Simpler than full gap-based merging: lines sharing the same block_id were in the same PDF block — merge them into one paragraph unconditionally (with hyphen handling). This won't catch cross-block continuation paragraphs but eliminates the most egregious single-line-per-paragraph fragmentation. Effort is very low.

Option C — Add a "verbose offline" mode that routes to Tier 1 instead Rather than improving the fallback, change the routing decision: if no API key is set, lower-confidence pages that scored, say, 65–84 (below the Tier 1 threshold but not critically complex) could be re-routed to Tier 1 instead of the digest fallback. The heuristic engine produces better paragraphs than the fallback does. Only truly unsalvageable pages (score 0, no text layer) would stay on the vision fallback path. This is a routing policy change, not a new extraction engine.

Option D — Warn the user more prominently At minimum, if the fallback fires on more than N pages, print a clear warning: "X pages used the offline fallback, which does not merge paragraphs. Output quality on those pages may be poor. Set an API key for better results." Low effort, honest, lets the user make an informed choice.

Realistic call: Option B (block_id grouping) as a quick win, then Option A if quality in offline mode becomes a stated goal. Option C is the most architecturally interesting — the Tier 1 engine is better than the fallback for anything that has a real text layer.

Problem 3: Two-column heuristic coarseness (100pt spread threshold)
