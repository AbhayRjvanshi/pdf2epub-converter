PART 2 — Global policies
2.1 Architecture invariant
CLI / REPL  →  Application  →  {Providers, Config, Validators}  →  Engine
Engine never imports app code. Providers/config/validators never import the engine (the LLMClient shape is re-declared locally as a Protocol in providers — no typing temptation). Enforced by a layer-isolation test (import scan), not by convention.
2.2 Engine-freeze policy + the five authorized seams
Modules frozen by default. A seam is permitted only if it is additive, default-preserving, and covered by dedicated regression tests. Exactly five, no others without plan amendment:
#	Seam	Semantics
S1	run_pipeline(..., validators: tuple[str,...] | None = None)	None = current behavior (both external tools); ("epubcheck",) = internal+EPUBCheck; () = internal only
S2	run_pipeline(..., event_cb: Callable[[PipelineEvent],None] | None = None)	Progress/error events; see schema below
S3	CancellationToken	Checked between pages, Tier-2 batches, repair attempts
S4	Phase 0.5 repair patch	Correctness fix, specced there
S5	run_pipeline(..., precomputed_reports: list[PageConfidenceReport] | None = None)	None = route internally as today; provided = Phase-3 routing skipped, preflight results reused (feeds vision-bypass ratio and Tier-2 batching unchanged)
Event schema (defined before implementation):
@dataclass(frozen=True)
class PipelineEvent:
    type: str        # phase_started | page_progress | tier2_batch_started
                     # | validation_started | repair_started | completed | failed
    phase: int
    page_index: int | None
    total_pages: int | None
    message: str
    metadata: dict
Callback failures: caught inside the engine, logged, never abort conversion. Cancellation flows only through the token, never via callback exceptions. CLI/REPL translates KeyboardInterrupt → token cancel → clean result, session intact.
2.3 Risk model
Engine-adjacent phases: engine-low-risk. Application layer: application-medium-risk — new user-visible behavior (credential policy, model filtering, cache location, validation policy) lives there regardless of engine stability.
2.4 Baseline discipline
Record reality: python --version; pytest --version; pytest --collect-only -q; timed run Measure-Command { pytest }; passed/skipped/failed; EPUBCheck/Ace availability. Skips stay skips — never recorded as failures.
2.5 Gate philosophy
Full suite (pytest -q, all pre-existing engine tests) after every phase. Area gates within phases. Packaging gates at Phases 2 and 15. If an old engine test fails because an app feature was added, the app change is wrong — full stop.

Phase 0.5 — Online self-repair: characterize, then fix
Goal: eliminate a verified content-loss defect before anything wraps the engine.
Verified defect mechanics (main.py): Phase 4B releases payloads per batch (req.layout_digest = None; req.raster_bytes = None). Phase 7 _repair_stream then calls handler.repair_page(req, ...) with those emptied requests → _batch_payload emits "layout_digest": [] → the model is asked to fix XHTML it cannot see. Tier2Request.is_vision (defined as raster_bytes is not None) flips to False after release, so vision pages get the text prompt and an empty digest. If the model returns empty output, parse_xhtml_to_stream_elements("") → [], and repaired = [e for e in repaired if e.page_num != page_idx] + [] deletes the page from the book. Separately, re.search(r"chapter_(\d+)", ...) is matched but unused — any chapter error re-prompts all Tier-2 pages (wasted spend).
Characterization tests (pin behavior first):
 1. digest repair receives a non-empty layout_digest;
 2. vision repair receives its original raster;
 3. route type survives payload release (vision stays vision);
 4. empty repair output → original page elements retained;
 5. parse-failure repair output → original retained;
 6. content-loss replacement (original had content, repair empty) → retained + warning logged;
 7. only pages in the failing chapter's page_nums ∩ Tier-2 pages are re-prompted;
 8. page order stable post-repair; loop terminates after max_repair_attempts; offline repair unchanged;
 9. rebuilt payloads are released after repair (memory guarantee survives);
10. repair responses are not written to the conversion cache (pin as deliberate).
Fix (narrow, additive — this is authorized seam S4):
- _repair_stream(..., doc=doc) (or a payload-rebuilder callback): rebuild via confidence_router.attach_payload(doc[idx], report) at repair time, release after — never reuse released requests;
- Tier2Request gains vision: bool | None = None; is_vision = explicit flag if set else derived from raster_bytes;
- replacement guard: new_elems empty/failed → keep original elements;
- re-prompt scoping: failing chapter file → ChapterRecord.page_nums ∩ Tier-2 pages;
- document: repair prompts carry validator-specific context → deliberately bypass the conversion cache.
Outcome: repair can only improve or preserve pages, never delete them; repair spend scoped to failing chapters.
Maintainability: the invariant "a repair must never replace a page with fewer semantic elements unless explicitly validated" is documented in code + tests, so future repair-policy changes start from a safe base.
Gate: full suite green; 10 new regression tests green.

Phase 5 — Credential resolver
Goal: one honest, headless-safe security boundary.
Resolution chain (explicit):
explicit runtime secret
  → provider-specific env var (OPENAI_API_KEY, ANTHROPIC_API_KEY, ...)
  → generic PDF2EPUB_API_KEY  (only if profile.allow_generic_key)
  → OS keyring (service="pdf2epub", username=provider_id)
  → unavailable
Provider-specific beats generic, always — documented, because silently shipping a generic key to an arbitrary OpenAI-compatible endpoint is a data-leak footgun.
Result: CredentialResolutionResult{credential, source: explicit|environment|keyring|unavailable, provider_id}.
Keyring boundary (v2.2 decision #15): optional dependency behind importlib.util.find_spec("keyring"); all keyring interaction wrapped at the boundary (KeyringError, backend-init failures, dbus absence — catch broadly); any failure → source=unavailable; silent unless debug logging; never writes to stderr on its own. Windows Credential Locker works as-is; headless Linux/CI/Docker degrade cleanly.
Logging rule: never key material, auth headers, or raw provider error payloads; allowed: provider id, source category, redacted error type.
Tests/edge cases: env beats keyring; provider env beats generic; generic ignored for non-opt-in profiles; keyring mocked (hit/miss/raises → unavailable); keyring not installed → unavailable; secret never appears in logs (string-scan assertion on captured logging); explicit secret path.
Outcome: credentials resolved or cleanly not; no crash modes.
Gate: tests/providers/test_credentials.py; full suite.

Level 1 — request validation (never opens the PDF): path exists & is file; output policy = not-a-directory + parent creatable + explicit overwrite semantics (default overwrite or --force — decide and test; never promises writability it can't prove); provider exists; model-in-catalog only when provider_id != "none" (decision #10: offline skips model validation); scalar bounds (batch_size ≥ 1, max_repair_attempts ≥ 0, font_sample_pages ≥ 1). Fails before any conversion work.
Level 2 — document preflight (online only): open PDF → confidence_router.route_document(doc, build_payloads=False) → derive required capabilities from the routing summary: tier2_digest > 0 ⇒ DIGEST_REQS; vision pages that will actually reach the model (i.e., not bypassed under the engine's dual policy: offline ⇒ bypassed; online ⇒ bypassed only when vision_ratio < 0.10 and not CMap-corrupted) ⇒ VISION_REQS → check the selected model against that set before a cent is spent; simultaneously yields a cost advisory (Tier-2 page counts) for the result/summary.
Memory contract (v2.2 pin): preflight holds zero payload bytes — build_payloads=False, full stop. The suite already pins triage laziness (test_payloads_are_lazy_by_default, test_triage_of_a_long_document_holds_no_payloads); add one app-level test asserting all preflight reports have raster_bytes is None and layout_digest is None.
Tests/edge cases: every Level-1 failure path; offline + conversion_model=None accepted; named provider + missing credential → CredentialError (not silent fallback); digest-only doc + text-only model → allowed; vision doc + text-only model → rejected pre-spend with a clear message; metadata-presence PDF + title=None → engine fallback preserved.
Outcome: requests are provably safe to execute or fail fast, cheaply.

Phase 12 — Session + command layer
Goal: application state and slash-commands as a reusable core (REPL now; anything later).
Session fields: pdf path, title/author (None = pending metadata), output path, provider id, model, validator prefs, last routing plan.
Invalidation rules (all tested): provider change → clear model + re-resolve credential; PDF change → re-derive metadata defaults + recompute readiness + drop stored routing plan; model change → revalidate vs catalog/capabilities.

PART 4 — Test architecture
Three levels: L1 unit (no network/binaries; every commit) · L2 application integration (SDKs/keyring/Java/Node mocked; real service/session/CLI wiring) · L3 E2E (real fixtures through the real engine; fake Tier-2; opt-in real-provider secret-gated tests).
Final tree:
tests/{engine,application,providers,validators,cli,config,package}/...
tests/packaging/test_distribution.py
tests/test_end_to_end.py   (until Phase 16 relocation)
Why this stays safe and sound: the pre-existing ~136-test engine suite is the non-negotiable regression floor after every phase; every new subsystem gets adversarial tests in its own layer; the architecture itself is tested (layer-isolation, monkeypatch-propagation, zero-payload preflight, no-secrets-in-logs/config).
Why it stays maintainable and scalable: adding a provider = a profile (data); adding a validator = protocol implementation + registration; adding a command = parser entry + command class; engine evolution = seams or nothing; config evolves via schema_version migrations; model churn via catalog lifecycle states — none of these require touching the conversion core.
